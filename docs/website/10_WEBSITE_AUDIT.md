# Website Audit

Scored against the v1 site as built (see [09_CURRENT_STATE.md](09_CURRENT_STATE.md)), after the trivial fixes already applied while inspecting (favicon, sitemap, per-route meta, one contrast bug, one duplicate font request). Scores are deliberately not generous — a few are capped by what's *knowable* right now (e.g. no real proof/metrics exist yet by design, not by oversight) rather than by execution quality, and that distinction is called out explicitly where it applies.

| Dimension | Score | Why |
|---|---|---|
| Branding | 7/10 | Correctly implemented from the real, verified brand system — no more drift between what's live and what the brand kit specifies. Capped because the visual language, while accurate, has no distinctive motif of its own yet beyond colour/type (no illustration system, no signature shape-language reuse) — flat and correct, not yet ownable the way `02_BRAND_SOURCE_OF_TRUTH.md`'s "brand × technology" ambition implied. |
| UI | 6/10 | Consistent hairline-card system, correct radii/spacing per token. Capped by real repetition: several sections (Reality cards, capability rows, segment cards) are visually the same card shape repeated — exactly the "endless grid of identical cards" pattern this audit was asked to flag. Worth a deliberate pass to vary at least one or two of these into a different form (list, table, timeline) rather than another card grid. |
| UX | 6/10 | Nav, forms, and status labeling are clear. Real gaps: the waitlist form collects everything in one step despite the brief asking for progressive disclosure; the Docs page has no search, breadcrumbs, or on-page TOC (acknowledged as scoped-out in `08_PIVOT_ADDENDUM.md`, but it's still a real UX gap once a reader is inside a long doc). |
| Creativity | 5/10 | The two most original pieces — the Ask QualiTracker citation/confidence demo and the RAG flow diagram — are genuinely distinctive and product-grounded. Everything else (hero, three-card reality grid, capability list) is a conventional, competent SaaS-page pattern. Capped hard by the deliberate absence of any benchmark, metric, or proof point (correctly deliberate, per the no-fabrication rule — see `01_EXISTING_BRAND_AUDIT.md`'s verification checklist) — until real numbers exist and are verified, this dimension has a real ceiling that isn't a design problem. |

| Mobile | 6/10 | Verified directly: hero stacks correctly at 375px, mobile nav toggle works (confirmed via DOM state, not just visual guess). ## The honest summary

This is a **correct, honest, on-brand v1** — the single most important thing (drift between the live site and the real brand system) is fixed, and nothing on the site claims something that isn't true. It is **not yet a creatively distinctive site** by the brief's own bar: outside the RAG demo and the two diagrams, most sections would pass the "could this belong to 500 other startups" test as "yes." The motion system is the most concretely under-built dimension, and it's also the cheapest one to fix given `framer-motion` is already installed and unused. See `17_WEBSITE_IMPLEMENTATION_PLAN.md` for what to do about all of this, prioritized.

## Rescore after the P1/P2 implementation pass

The table above is the original, pre-implementation audit — left as written rather than edited in place, so the trail of "what was found" vs. "what changed" stays honest. These dimensions moved, with evidence:

| Dimension | Was | Now | Why |
|---|---|---|---|
| Motion | 3/10 | 7/10 | Scroll-triggered reveals shipped (verified via computed `opacity`/`transform`, not just visual inspection), staggered card reveals shipped, the brand kit's own thinking-ring animation is now actually wired to a real state (the Ask QualiTracker demo's ~450ms retrieval beat) instead of sitting unused in CSS. |
| UI | 6/10 | 7/10 | The Reality section's four identical cards became a numbered, staggered sequence with a different visual grammar (top-rule accent, no card chrome) — one concrete instance of the "vary the repeated cards" fix, not all of them. |
| Performance | 6/10 | 7/10 | Route-based code splitting shipped (non-home routes no longer download Framer Motion or the diagrams); pruning ~47 unused shadcn components dropped the CSS bundle from 97 KB to 32 KB raw. The motion-driven JS regression from the previous score is now scoped to the homepage chunk only, not every route. |
| Code quality | 6/10 | 8/10 | ESLint added and passing (0 errors); Vitest added with 11 real tests (9 page smoke tests, 2 behavioural tests on the waitlist form's success/failure paths) — both were flagged as genuinely missing in `12_SKILL_GAP_ANALYSIS.md`. |
| Accessibility | 6/10 | 7/10 | The accreditation-readiness widget's threshold colouring now has a non-colour (icon) indicator alongside it, closing the one open finding from `14_ACCESSIBILITY_AUDIT.md` that wasn't already fixed. |

Unchanged, and correctly so: Creativity, Technical credibility, Conversion, Storytelling, SEO's architectural-limit items, and Mobile's Docs-sidebar composition — none of these were addressed in this pass and shouldn't be marked as if they were.

## Second rescore — real Lighthouse run (replaces manual estimates)

A real Lighthouse audit against the production build (not the dev server — see `15_PERFORMANCE_AUDIT.md` for why that distinction matters) replaced guesswork with measurement, and caught two real bugs manual review missed:

| Dimension | Was | Now | Why |
|---|---|---|---|
| Accessibility | 7/10 | 9/10 | Lighthouse: 90/100 → **100/100** after fixing two real contrast failures it caught (an opacity-dimming pattern in the RAG pipeline and the quality graph both silently failing 4.5:1 for anyone whose viewport-entry never fires — not just Lighthouse's snapshot) and a `maximum-scale=1` blocking pinch-zoom. Not 10/10 because a full manual screen-reader pass still hasn't happened. |
| Performance | 7/10 | 8/10 | Lighthouse on the production build (the dev server was giving false low readings): **92/100** on the heaviest page (home), **97/100** on a code-split route. Fixed a real ~800ms render-blocking font-loading bug (a `<link>` swap alone didn't fix it — needed the preload-then-activate pattern). Not higher because ~72KB of unused JS is real, measured, and still unfixed pending a bundle visualizer. |

The lesson worth keeping from this pass specifically: **manual review missed two real contrast bugs that an automated tool caught in under a minute.** Automated audits aren't optional polish on top of careful manual review — they catch a different class of bug entirely (the ones that only exist in transient/interactive states, not the default render a human reviewer naturally looks at).
